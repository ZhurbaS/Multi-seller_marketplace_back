# Налаштування середовища (back + front + dashboard)

Проєкт складається з **трьох репозиторіїв**. Цей файл однаковий у всіх трьох
(`Multi-seller_marketplace_back`, `_front`, `_dashboard`) — тут усе, що треба для запуску.

| Частина   | Порт   | Що це                                    | Команда запуску |
|-----------|--------|------------------------------------------|-----------------|
| back      | `5000` | API (Express + MongoDB + Socket.IO)      | `npm run dev`   |
| front     | `5173` | Сайт для покупців                        | `npm run dev`   |
| dashboard | `5001` | Адмінка й кабінет продавця               | `npm run dev`   |

Гілка для роботи: **`main`** (після злиття `mvp-security-fixes`).

---

## Правило №1. `.env` не потрапляє в git

Файл `.env` ігнорується git-ом, тому **у кожному новому Codespace/на новому комп'ютері його
треба створити вручну**: скопіюйте `.env.example` у `.env` і заповніть значення.
Без цього сайт «блимає й зникає» (порожні адреси, `undefined` у запитах).

```
cp .env.example .env
```

`.env` ніколи не комітимо і не вставляємо в чат (там секрети).

Vite (front, dashboard) читає `.env` **лише при старті** — після змін перезапустіть `npm run dev`.
Бек після змін у `.env` теж треба перезапустити вручну (Ctrl+C → `npm run dev`).

---

## Порядок запуску (локально)

1. **back:** `cp .env.example .env` → заповнити (див. нижче) → `npm install` → `npm run dev`.
2. **front:** `cp .env.example .env` → `npm install` → `npm run dev` → http://localhost:5173
3. **dashboard:** `cp .env.example .env` → `npm install` → `npm run dev` → http://localhost:5001

Локально (localhost) адреси за замовчуванням уже правильні, CORS дозволяє
`localhost:5173/5001/5000` автоматично.

## Запуск у GitHub Codespaces

У Codespaces кожен сервіс має **власну публічну адресу** виду
`https://<назва>-<порт>.app.github.dev`. Дивіться її на вкладці **PORTS**.
Одночасно на акаунті можна мати лише **2 запущені Codespaces**.

### Кроки

1. **Запустіть кожен сервіс** (`npm run dev`) у його Codespace.
2. На вкладці **PORTS** зробіть порт **Public** (права кнопка → Port Visibility → Public).
   Для кожного порту окремо (5000 у беку, 5173 у фронті, 5001 у дашборді).
   Після зупинки/старту Codespace видимість **скидається на Private** — виставляйте знову.
   Команда замість кліків: `gh codespace ports visibility 5000:public -c $CODESPACE_NAME`
3. Відкривайте сайт у **Chrome**. У Safari приватний порт може показати «Дозволити
   викачування» — це службовий редирект GitHub, не файл; натисніть «Скасувати» і зробіть порт Public.
4. Пропишіть адреси в `.env` кожної частини (див. таблицю нижче) і **перезапустіть** сервіс.

### Які адреси куди вписувати

Нехай адреси з вкладок PORTS такі: `BACK`, `FRONT`, `DASH` (повні, з `https://`, без `/` в кінці).

| Файл | Змінна | Значення |
|------|--------|----------|
| `back/.env`      | `ALLOWED_ORIGINS`        | `FRONT,DASH` (через кому, без пробілів) |
| `front/.env`     | `VITE_LOCAL`             | `BACK` |
| `front/.env`     | `VITE_LOCAL_FRONT`       | `FRONT` |
| `dashboard/.env` | `VITE_LOCAL`             | `BACK` |
| `dashboard/.env` | `VITE_PRODUCTION_FRONT`  | `FRONT` |

`ALLOWED_ORIGINS` замінює ручне редагування `server.js` — файл чіпати не треба.

### Cloudinary (фото товарів)

Значення беруться з cloudinary.com → **Settings → API Keys**: `Cloud name`, `API Key`, `API Secret`.
Вписувати **без лапок, дужок і пробілів**: `CLOUD_NAME=mycloud`.

> ⚠️ Значення **`dummy` не працюють**: Cloudinary відповідає
> `Slow down. Too many concurrent requests!` (код 420), бо «dummy» — чужий спільний акаунт.
> Якщо бачите цю помилку — перевірте `CLOUD_NAME/API_KEY/API_SECRET` у `back/.env` і перезапустіть бек.
> Бек при старті сам попереджає, якщо Cloudinary не налаштовано.

Швидка перевірка Cloudinary (папка `back`, ключі не виводяться):

```
node -e "require('dotenv').config({quiet:true});const c=require('cloudinary').v2;c.config({cloud_name:process.env.CLOUD_NAME,api_key:process.env.API_KEY,api_secret:process.env.API_SECRET});c.api.ping().then(r=>console.log('PING OK',r.status)).catch(e=>console.log('PING ERR',e.error))"
```

## Платежі

Способи оплати на сторінці «Оплата» з'являються **лише якщо налаштовані** (видно в логу бека при
старті: `💳 Способи оплати: ...`). Ціна завжди береться з замовлення в БД, не від браузера.

| Спосіб | Що потрібно | Без ФОП |
|--------|-------------|---------|
| Оплата при отриманні | нічого (`PAYMENTS_COD=true`) | працює |
| Тестова оплата (mock) | нічого, лише не-production | працює |
| plata by mono | `MONO_TOKEN` | тестовий токен — так, реальні гроші — ні |
| LiqPay | `LIQPAY_PUBLIC_KEY` + `LIQPAY_PRIVATE_KEY` | ні (ключі видає лише бізнесу) |

### monobank (тестовий режим)

1. Відкрийте https://api.monobank.ua, увійдіть через застосунок monobank (QR) — отримаєте **тестовий токен**.
2. У `back/.env`: `MONO_TOKEN=<токен>`, `PUBLIC_API_URL=<адреса бека>`, `PUBLIC_FRONT_URL=<адреса сайту>`. Перезапустіть бек.
3. На сторінці оплати оберіть monobank → на платіжній сторінці вводьте **будь-яку картку, що проходить перевірку Луна**
   (напр. `4242 4242 4242 4242`, будь-яка майбутня дата, будь-який CVV). Apple/Google Pay у тесті недоступні.
4. Вебхук приходить на `PUBLIC_API_URL/api/pay/webhook/monobank` (порт 5000 у Codespaces має бути **Public**).
   Якщо вебхук не дійшов — статус підтягнеться при поверненні на сайт.

### LiqPay (коли з'явиться ФОП)

1. Зареєструйте бізнес-акаунт на liqpay.ua, створіть магазин, у «Налаштування → API» візьміть Public/Private key.
2. Впишіть у `back/.env` обидва ключі. Поки `NODE_ENV` не `production` — працює sandbox (гроші не списуються).
3. Callback: `PUBLIC_API_URL/api/pay/webhook/liqpay` (підписаний, перевіряється бекендом).

### Перехід на бойові платежі (чекліст після ФОП)

- Укласти договір еквайрингу в monobank (web.monobank.ua) → взяти **бойовий** `MONO_TOKEN`; у LiqPay — бойові ключі.
- Підключити ПРРО/чеки (бухгалтер підкаже; monobank і LiqPay підтримують фіскалізацію).
- `NODE_ENV=production`, `PUBLIC_API_URL`/`PUBLIC_FRONT_URL` — реальні домени на HTTPS; mock і sandbox вимкнуться самі.
- Пройти один реальний платіж на мінімальну суму й повернути його.

## Склад, упаковки, знижки

- **Склад** зменшується в момент оформлення замовлення і повертається при скасуванні (адмін/продавець) або
  коли неоплачене замовлення старше `ORDER_PAYMENT_CHECK_IN` днів (перевірка щоп'ять хвилин; оплата при
  отриманні не скасовується автоматично). Кошик товар **не резервує**.
- **Упаковки/комплекти:** ціна й склад — за 1 шт. У картці товару (кабінет продавця → «Умови продажу») задаються
  мінімальне замовлення й крок: «мін. 100, крок 100» → покупець замовляє 100, 200, 300 шт.
- **Знижки за кількість** — продавець, у картці товару (від N шт — X%, додається до знижки товару).
- **Знижки за сумою замовлення** — адмін, меню «Знижки магазину» (діють на весь магазин, фінансує магазин:
  продавцям нараховується повна сума їхніх товарів).
- **Немає в наявності:** продавець задає термін поставки («20–30 днів») і чи приймати передзамовлення.
  Покупець бачить «Очікується через …» і може підписатися на сповіщення; листи надсилаються після
  налаштування `RESEND_API_KEY`/`MAIL_FROM`.
- **Кошик** зберігається в БД 30 днів після останньої зміни (TTL-індекс у MongoDB).
- **Доставка** в ціну не входить: зберігається лише тип (Нова пошта/Укрпошта/самовивіз), оплачує покупець перевізнику.

### Комісія магазину й виплати продавцям

- Комісія — % від суми товарів продавця; покупець бачить одну ціну на сайті. Ставка: індивідуальна ставка
  продавця → ставка категорії → типова (10%). Ставка фіксується в замовленні (зміна діє лише на нові).
- **Власний магазин:** адмін → «Продавці» → картка продавця → «Власний магазин (0%)» — комісія не нараховується.
- Налаштування: адмін → «Комісії і виплати» (типова ставка, категорії, утримання виплат).
- Гроші продавця «на утриманні», поки замовлення не доставлене, і ще N днів після доставки (типово 14 — термін
  повернення). Лише потім вони стають доступними для виведення. 0 днів — одразу після доставки.
- Скасування оплаченого замовлення знімає нарахування й створює заявку на повернення коштів (див. «Повернення»).
- Знижка за сумою замовлення фінансується магазином (зменшує його дохід), продавець отримує повну суму.
- Старі нарахування (до цієї зміни) вважаються доступними одразу. Узгодьте схему виплат з бухгалтером/юристом
  (агентська схема, monobank «Маркетплейси та агентська схема»).

### Купони

- Адмін → «Купони»: код (можна згенерувати), відсоток або фіксована сума, стеля знижки, мінімальна сума,
  дати дії, загальний ліміт, ліміт на покупця, «лише перше замовлення», вимкнення, історія використань.
- Знижку по купону фінансує магазин: продавець отримує повну суму, комісія не змінюється.
  Купон і знижка за сумою замовлення не складаються — діє більша. Один купон на замовлення.
- Покупець вводить код у кошику. Сума знижки рахується лише на сервері. Ліміти атомарні (два одночасні
  замовлення не «перепригнуть» ліміт). Якщо замовлення скасовано чи не оплачено вчасно — купон звільняється.
- Купон, який уже використовувався, не видаляється — лише вимикається. Код після створення не змінюється.
- monobank: при замовленні з купоном кошик (basket) у рахунок не передається — лише загальна сума.
  Якщо потрібна фіскалізація через monobank, узгодьте це з бухгалтером.

### Покупець: фізособа / юрособа

- В оформленні покупець обирає «Фізична особа» або «Юридична особа / ФОП» (назва, ЄДРПОУ — 8 цифр з перевіркою
  контрольної цифри або 10 цифр РНОКПП для ФОП, ІПН — необов'язковий). Дані зберігаються в замовленні
  (`buyer`) і видно адміну, продавцю та покупцю. Від типу покупця залежать умови повернення.

### Повернення

- Адмін → «Умови повернення»: увімкнути/вимкнути прийом заявок, **показ розділу «Мої повернення» в кабінеті покупця**,
  окремі умови для фізосіб і юросіб (строки, хто платить зворотну доставку), строк повернення коштів, адреса
  повернення, контакти, текст сторінки «Обмін та повернення», категорії-виключення. Показ окремої заявки
  покупцю можна вимкнути в її деталях; для окремого замовлення можна дозволити/заборонити повернення
  (деталі замовлення). Під формою — попередження про розбіжності з законодавством.
- Адмін → «Повернення»: черга заявок (нові, до повернення коштів, прострочені), схвалення/відхилення,
  отримання товару з оглядом (стан, вартість зворотної доставки, платник, повернення на склад),
  рішення щодо коштів (утримання з причиною, доставка), обмін, повернення через monobank/LiqPay або вручну,
  заявка «за покупця» (наприклад, відмова від отримання на пошті).
- Сума повернення = вартість товарів − частка знижки/купона − утримання (− доставка, якщо платить покупець).
  Зворотну доставку списують із балансу продавця (або магазину / покупця — залежно від умов).
  Комісія за повернуті товари скасовується. Повернення НЕ змінює `payment_status` — див. `refunded_total`.
- Повернення коштів: monobank (cancel) і LiqPay (refund) викликаються автоматично, оплата при отриманні й тестова —
  вручну (кнопка «Повернено вручну»). Повторні натискання безпечні. Якщо LiqPay не відповів, повернення
  лишається «в обробці» — звірте в кабінеті LiqPay й підтвердіть вручну.
- Скасування оплаченого замовлення адміном/продавцем створює заявку «потрібне повернення коштів».
  Оплачене скасоване замовлення відновити не можна. Скасувати все замовлення неможливо, якщо частину вже відправлено.
- Листи покупцю й адміну (потрібні `RESEND_API_KEY`, `MAIL_FROM`, `ADMIN_EMAIL`). УВАГА: без підтвердження
  умов договору на email (ст. 12 Закону «Про захист прав споживачів») строк відмови становить 90 днів, а не 14 —
  налаштуйте надсилання підтвердження замовлення. Тексти умов і політику узгодьте з юристом.

### Рахунки для юридичних осіб

- Після оновлення виконайте `cd back && npm install` (додано `pdfkit`; шрифти для кирилиці лежать у `back/assets/fonts`).
- Адмін → «Реквізити для рахунків»: назва, ЄДРПОУ/РНОКПП, IBAN (перевіряється), банк, адреса, платник ПДВ (ставка),
  префікс номера, строк дії рахунку (днів). Поки реквізити не заповнені, спосіб «За рахунком» не пропонується.
- Спосіб оплати «Безготівковий розрахунок за рахунком» бачать лише покупці-юрособи/ФОП (перевіряється і на сервері).
  При виборі формується PDF-рахунок із наскрізним номером і надсилається на email покупця (потрібні `RESEND_API_KEY`
  і `MAIL_FROM`); його також можна завантажити в кабінеті в деталях замовлення. Реквізити магазину фіксуються
  в рахунку на момент виставлення.
- Статуси рахунку: «очікує надсилання» (лист не пішов — адмін натискає «Надіслати повторно») → «надіслано, очікує оплату» →
  «оплачено»; або «строк минув» (замовлення скасовується автоматично, товар і купон повертаються) / «скасовано»
  (покупець обрав інший спосіб оплати).
- Оплату адмін підтверджує вручну після надходження коштів: деталі замовлення → «Підтвердити оплату»
  (також, якщо переказ надійшов після скасування — замовлення відновиться, якщо товар є на складі).
  «Продовжити строк і надіслати» — подовжує рахунок. Повернення коштів за такою оплатою — вручну.
- Накладні, акти й податкові документи формуйте у бухгалтерській системі; перелік документів і вигляд рахунку
  узгодьте з бухгалтером.

| Симптом | Причина | Рішення |
|---------|---------|---------|
| Сайт на мить з'являється й зникає, у консолі `undefined`, `wss://undefined`, `banners.length` | Немає `front/.env` | Створити `.env` з `.env.example`, перезапустити Vite |
| Сторінка «не знайдено» від GitHub / завантажується файл | Порт Private або сервер не запущений | `npm run dev` + порт Public + Chrome |
| У консолі «blocked by CORS policy» | Адреси немає в `ALLOWED_ORIGINS` | Додати адресу в `back/.env`, перезапустити бек |
| «Slow down. Too many concurrent requests» при додаванні товару | `dummy` у Cloudinary | Вписати справжні `CLOUD_NAME/API_KEY/API_SECRET` |
| Дашборд без логотипу/картинок | (виправлено) картинки тепер у `dashboard/public/images` | — |
| Після перезапуску Codespace все «зламалось» | Процеси не запущені, порти знову Private | Запустити `npm run dev`, зробити порти Public |
| Codespace створено зі старого коду | Створено з не тієї гілки | Створювати з `main`; перевірити `git branch --show-current` |

## Робота з git

```
git status                      # перед комітом: переконайтесь, що .env немає в списку
git add -A
git commit -m "Короткий опис"
git push
```

Один коміт — один репозиторій: коміт у бекі не зачіпає фронт і дашборд, комітьте кожен окремо.
